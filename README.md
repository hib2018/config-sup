# config-sup

ローカルの設定を探し、設定項目の変更案を人間が確認してから適用するCLI/TUIです。Web UIはありません。GoがCLIを動かし、Node.jsはPiエージェントとYAML/TOMLの処理に使用します。

## 起動

Go 1.23以降、Node.js 22以降、Piで設定済みのモデル・認証が必要です。対話端末から起動してください。標準のTUIには `fzf` が必要です（番号式CLIでは不要）。

初回のみ、リポジトリ内で依存関係とコマンドを用意します。`~/.local/bin` がPATHに入っていない場合は、シェルの設定で追加してください。

```sh
npm install
mkdir -p "$HOME/.local/bin"
ln -s "$PWD/bin/config-sup" "$HOME/.local/bin/config-sup"
```

その後は**どのディレクトリからでも**起動できます。

```sh
config-sup                  # TUI：検索・矢印キーで項目を選ぶ
config-sup "Zed エディタ"     # ツール名を先に渡す場合
config-sup --cli            # fzfを使わない番号式CLI
```

ツール名を省略すると `tool: ` と表示して尋ねます。確認への入力は `y` が承認、`N` またはEnterが中止です。リポジトリ内から `./bin/config-sup` で起動することもできます。コマンドのリンクはこのリポジトリを参照するため、リポジトリを移動した場合はリンクを作り直してください。npmは初回の依存関係導入に使用します。

1. 同意後、`~/.config` と `~/Library/Application Support` 内のJSON・YAML・TOML設定を探し、**ファイル名・キー名・型（現在値は除く）**をPiモデルに送って対象を特定します。候補が複数なら人間が選びます。初期範囲で特定できない場合だけ、別途同意を得て `/Applications` と `~/Applications` の**アプリ名のみ**を検索します。アプリ本体は設定の書き込み先にはしません。
2. 設定項目名と現在値を一覧表示します。1項目を選びます。文字列・数値では別途同意があれば、選んだ設定のディレクトリ（追加探索で見つけたアプリ本体も含む）から限定されたソースコードやスキーマを読み、そのファイル名と必要な内容をPiモデルに送って**コードに根拠のある選択肢候補**を調べます。選択肢は参考情報で、自由入力も可能です。真偽値は `true`/`false` です。
3. 設定内容を `変更前 → 変更後` で示します。元ファイルはこの時点では変更されません。`y` で明示的に承認した場合だけ、元ファイルの変更を再検査し、同じディレクトリに権限0600のバックアップを作ってから適用します。承認しない場合は書き込みません。設定ツールの再起動や外部サービスの変更はしません。

## 制限と安全性

- 追加探索は**アプリ名による対象特定のみ**です。初期範囲に編集可能な設定ファイルがない場合は停止します。新しい設定ファイルの生成や、アプリ本体の編集は行いません。その他のディレクトリへの探索は未対応です。
- 対応する変更は既存のJSON・YAML・TOMLにある文字列・数値・真偽値の**1項目／1回**。JSONは全体を整形して書き直し、YAML/TOMLは対象の単純な値だけを置換します。JSONCの書き戻しや配列・null・新規キーは未対応です。
- エージェントの選択肢候補は、読んだソース内の引用と照合しますが、意味が正しいことを保証するものではありません。tree-sitterは導入しておらず、既存の形式別パーサーと限定的なコード読取で対応しています。モデルに送る前に提示される範囲と目的を確認してください。
- バックアップの保存先は適用時に表示されます。復元する場合は、設定ツールを終了してからバックアップ内容と対象を確認し、手動でコピーしてください。失敗時もバックアップが残ることがあります。
- モデル・認証を使用した実機での通し操作は未検証です。`npm test` でモデルに依存しない検証を実行できます。
