# config-sup

ローカルの設定を探し、設定項目の変更案を人間が確認してから適用するCLI/TUIです。Web UIはありません。GoがCLIを動かし、Node.jsはPiエージェントとYAML/TOMLの処理に使用します。

## 起動

Go 1.23以降、Node.js 22以降、Piで設定済みのモデル・認証が必要です。対話端末から起動してください。標準のTUIには `fzf` が必要です（番号式CLIでは不要）。

初回のみ、リポジトリ内で依存関係とコマンドを用意します。`~/.local/bin` がPATHに入っていない場合は、シェルの設定で追加してください。

```sh
npm install
mkdir -p "$HOME/.local/bin"
ln -s "$PWD/bin/config-sup" "$HOME/.local/bin/config-sup"
```

その後は**どのディレクトリからでも**起動できます。

```sh
config-sup                  # TUI：番号を入力してSpaceで編集
config-sup "Zed エディタ"     # ツール名を先に渡す場合
config-sup --cli            # fzfを使わない番号式CLI
```

ツール名を省略すると `tool: ` と表示して尋ねます。**適用時だけ**確認します。`y` が承認、`N` またはEnterが中止です。リポジトリ内から `./bin/config-sup` で起動することもできます。コマンドのリンクはこのリポジトリを参照するため、リポジトリを移動した場合はリンクを作り直してください。npmは初回の依存関係導入に使用します。

1. `~/.config` と `~/Library/Application Support` 内のファイルを**拡張子で限定せず**候補にし、機密候補を除外したファイル名・キー名・型（現在値は除く）をPiモデルに送って対象を特定します。候補が複数なら `1,2` のように複数選択できます。設定ディレクトリへのリンクは参照先（最大500ファイル・深さ6段）を自動で探索します。初期範囲で特定できない場合だけ `/Applications` と `~/Applications` のアプリ名を探します。いずれも個別確認はありません。リンク自体やアプリ本体は書き換えません。
2. 選択したファイルの項目を**一つの一覧**にまとめ、Piによる日本語の説明・現在値・選択肢を表示します。最大100項目まで。TUIでは番号を入力してSpaceで編集し、Enterで編集を終えます。`--cli` では番号（末尾Spaceも可）を入力してEnter、空欄で編集を終えます。真偽値は切り替え、コードで裏付けた選択肢は次の候補に進み、それ以外の文字列・数値は自由入力します。何度でも別項目を編集できます。同名項目の重複や説明を取得できない項目は編集を停止します。限定されたソースやスキーマの読取・Piへの送信も個別確認なしで行います。項目の現在値は説明依頼に直接渡しません（ソースコードに値が含まれる場合はモデルが読む可能性があります）。選択肢はソース内の引用と照合します。
3. 編集した全項目を `変更前 → 変更後` でまとめて示します。この時点ではファイルを変更しません。`y` で承認した場合だけ全対象を再検査し、バックアップを作って適用します。通常のバックアップは元ファイルと同じディレクトリに権限0600で保存します。リンク先の場合は `~/.local/state/config-sup/backups` に保存します。承認しなければ書き込みません。ツールの再起動や外部サービスの変更はしません。

## 制限と安全性

- 追加探索は**アプリ名による対象特定のみ**です。初期範囲に編集可能な設定ファイルがない場合は停止します。新しい設定ファイルの生成や、アプリ本体の編集は行いません。その他のディレクトリへの探索は未対応です。
- **発見時にファイル形式は限定しません**。編集は検証できる既存項目に限ります。JSONは全体を整形し、YAML/TOMLは単純な値を置換します。その他の形式でも、曖昧さのない1行の `key = value` は値だけを置換し、コメント等を残します。複雑な構文、重複キー、JSONCの書き戻し、配列・null・新規キーは未対応です。対応できないファイルを推測で書き換えません。
- エージェントは名前と既知のキー情報から候補ファイルを選びます。未知の形式は選択後にローカルで解析します。発見時に内容をローカルで検査して機密候補を除外し、設定値はモデルへの項目一覧に含めません。`.env`、認証・トークン・秘密鍵らしいパス、機密語や長い不透明文字列を含むファイルはモデルに渡す前に機械的に除外します。ソース内容も読取ツール内で同様に検査します。ただし検出はヒューリスティックであり、未知の秘密を完全には判定できません。機密情報のある環境では実行しないでください。説明はモデルによる参考情報で、選択肢候補はソースの引用と照合しますが意味の正しさは保証しません。tree-sitterは導入せず、形式別パーサーと限定的なコード読取を使用します。
- バックアップの保存先は適用時に表示されます。復元する場合は、設定ツールを終了してからバックアップ内容と対象を確認し、手動でコピーしてください。失敗時もバックアップが残ることがあります。
- モデル・認証を使用した実機での通し操作は未検証です。`npm test` でモデルに依存しない検証を実行できます。
